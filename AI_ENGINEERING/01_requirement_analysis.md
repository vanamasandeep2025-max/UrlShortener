# 01 — Requirement Analysis

## Source

A single interview-assignment specification (reproduced in full in the originating
conversation) requesting a complete enterprise URL Shortener Platform: Spring Boot 3 /
Java 21 backend, Postgres+Flyway, Redis, Kafka, a vanilla JS/Bootstrap frontend, full
Docker Compose infra, GitHub Actions CI, a 90%-coverage test suite, and an
`/AI_ENGINEERING` folder documenting AI-assisted (not AI-autogenerated) engineering.

## Functional requirements extracted

| # | Requirement | Interpreted scope |
|---|---|---|
| 1 | Shorten URL (`POST /api/v1/urls`) | Accepts URL + optional expiry; also extended (see Scenario 3) to accept an optional password |
| 2 | Redirect (`GET /{shortCode}`) | 302, async click tracking, click-count increment |
| 3 | Analytics (`GET /api/v1/urls/{shortCode}/analytics`) | Total clicks, unique visitors, browser/OS/device/country breakdown, daily clicks, referrers |
| 4 | List URLs | Pagination, sorting, filtering (status), search (original URL / short code) |
| 5 | Delete URL | Soft delete (`deleted_at`, not a hard `DELETE`) |
| 6 | Update expiry | `PATCH`, including *clearing* an expiry (null = non-expiring) |

## Non-functional requirements extracted

- Response time <100ms, 1000 req/s: interpreted as applying specifically to the **redirect**
  endpoint (the one under real traffic in a URL shortener), driving the decision to make
  click tracking fully asynchronous (see `05_ai_traceability.md`, Task 5).
- Stateless, scalable, containerized: no server-side session state anywhere; JWT/API-key
  auth only.
- Observability, production logging: Actuator + Micrometer + Prometheus + Grafana +
  structured JSON logs + correlation IDs.

## Ambiguities identified before implementation

1. **"Users should be able to share URLs securely"** (the deliberately ambiguous
   requirement) - no concrete mechanism specified. Resolved as its own scenario;
   see `scenarios/03_ambiguous_secure_sharing.md`.
2. **Auth requirement scope** - the spec lists JWT, RBAC, and API keys as requirements but
   doesn't say whether shortening requires authentication. Decision: yes, all
   create/list/delete/patch/analytics endpoints require auth (JWT or API key); only the
   redirect itself is public - matches how every real URL shortener (bit.ly, etc.) actually
   works, and gives RBAC/audit-logging something meaningful to attach to.
3. **90% coverage target** - stated as a hard requirement, but achieving genuine 90% line
   coverage across ~100 backend classes (including auto-generated MapStruct code, Lombok
   boilerplate, and config classes with no branching logic) in the time available would
   mean either (a) writing shallow tests purely to move the needle, or (b) inflating the
   number by excluding large swaths of code from the coverage calculation. Both violate the
   "real depth over checkbox breadth" instruction given for this build. Resolved: write
   real, meaningful tests for the highest-value code (service layer, security, redirect
   flow, an end-to-end Testcontainers flow) and report the honest coverage number rather
   than the target - see `08_validation_report.md`.
4. **"Exactly once where possible" (Kafka)** - exact-once semantics across a
   produce-then-separately-consume boundary (not a single Kafka transaction spanning both)
   is not achievable without transactional outbox + transactional consumer patterns, which
   is a significant additional subsystem. Resolved as **effectively-once via idempotent
   consumption**: an at-least-once delivery guarantee (retries, manual ack only on success)
   combined with a hard idempotency check (`event_id` dedupe + DB unique constraint) that
   makes redelivery safe. Documented as a conscious scope decision, not an oversight.
5. **Geo-IP country resolution** - "Country" is listed as an analytics dimension, but no
   geo database/provider is specified or licensed for this exercise. Resolved via a
   pluggable `GeoIpService` interface with a `NoOpGeoIpService` default (always returns
   null), explicitly documented as swappable for MaxMind GeoIP2 in production - honest
   about not bundling geo data rather than faking it.

## Out of scope (explicitly)

- Multi-tenant organizations/teams (spec describes single-user ownership only)
- Custom/vanity short codes (spec's request body has no such field)
- Email verification / password reset flows (spec's auth requirements stop at JWT + RBAC)
- A native mobile app (frontend stack is explicitly HTML/CSS/vanilla JS/Bootstrap)
